# Safe Account Setup, Owners and Modules

Every AbstractionKit Safe account class has these methods: [Safe Unified Account](/wallet/abstractionkit/safe-unified-account) (`SafeMultiChainSigAccountV1` and `SafeMultiChainSigAccountV2`, the recommended classes), [Safe Account V3](/wallet/abstractionkit/safe-account-v3) (`SafeAccountV0_3_0`) and [Safe Account V2](/wallet/abstractionkit/safe-account-v2) (`SafeAccountV0_2_0`). Calldata, signing and sending methods are on [Safe Account Transactions and Signing](/wallet/abstractionkit/safe-account-signing).

The examples import `SafeAccountV0_3_0 as SafeAccount`. Each method on this page is called the same way on `SafeMultiChainSigAccountV1`, `SafeMultiChainSigAccountV2` and `SafeAccountV0_2_0`: change the import to your class. Where a class differs (UserOperation type, default addresses, example output), the section says so.

## Account Address and State

### isDeployed

Static method that checks whether a Safe account is already deployed on-chain. Use it to decide between connecting to an existing account (`new SafeAccountV0_3_0(address)`) and initializing a counterfactual one (`SafeAccountV0_3_0.initializeNewAccount(owners)`). Once an account is deployed, the factory data carried by `initializeNewAccount` is no longer needed and including it would waste gas.

The same static method exists on every Safe class, for example `SafeMultiChainSigAccountV1.isDeployed(...)`.

This only checks for non-empty bytecode at `accountAddress`. It does not verify that the deployed code is a Safe or that its on-chain configuration matches a given owner set.

#### Usage

<Tabs>
<TabItem value="example.ts" label="example.ts">

```ts title="example.ts"
import { SafeAccountV0_3_0 as SafeAccount } from "abstractionkit";

const accountAddress = "0x1a02592A3484c2077d2E5D24482497F85e1980C6";
const nodeRpcUrl = "https://ethereum-sepolia-rpc.publicnode.com";

const account = (await SafeAccount.isDeployed(accountAddress, nodeRpcUrl))
    ? new SafeAccount(accountAddress)
    : SafeAccount.initializeNewAccount([ownerPublicAddress]);
```

## Owners

### createAddOwnerWithThresholdMetaTransactions

Builds the MetaTransactions needed to add a new owner (an ECDSA address or a WebAuthn public key) and set a new threshold. If the new owner is a WebAuthn signer whose verifier contract is not yet deployed, the returned list also contains a MetaTransaction that deploys the verifier, so it resolves to one or two MetaTransactions.

```ts
createAddOwnerWithThresholdMetaTransactions(
  newOwner: Signer,
  threshold: number,
  overrides?: {
    nodeRpcUrl?: string | Transport | JsonRpcNode;
    eip7212WebAuthnPrecompileVerifier?: string;
    eip7212WebAuthnContractVerifier?: string;
    webAuthnSignerFactory?: string;
    webAuthnSignerSingleton?: string;
    webAuthnSignerProxyCreationCode?: string;
  },
): Promise<MetaTransaction[]>
```

`overrides.nodeRpcUrl` is required when adding a WebAuthn owner, so the SDK can check whether the new owner's verifier is already deployed.

On `SafeMultiChainSigAccountV1` and `SafeMultiChainSigAccountV2`, a passkey owner is derived with the class's own Safe Passkey module v0.2.1 defaults, so the added owner is the signer the account signs with. Pass WebAuthn overrides only if you created the account with custom WebAuthn values.

### createStandardAddOwnerWithThresholdMetaTransaction

Builds the single standard `addOwnerWithThreshold` MetaTransaction for an owner public address. Unlike the plural variant above, it takes a plain address, performs no WebAuthn verifier handling, and returns synchronously.

```ts
createStandardAddOwnerWithThresholdMetaTransaction(
  newOwner: string,
  threshold: number,
): MetaTransaction
```

```ts title="example.ts"
const addOwnerMetaTransaction =
    smartAccount.createStandardAddOwnerWithThresholdMetaTransaction(
        "0xNewOwnerAddress",
        2, // new threshold
    );
```
