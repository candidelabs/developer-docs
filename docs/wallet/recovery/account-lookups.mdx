# Recovery Request Lookups by Account

These two endpoints of the [Recovery UX API](/wallet/recovery/ux-api/) find a Safe account's recovery requests by account address instead of by request ID. Start with the [UX API reference](/wallet/recovery/ux-api/) for the main flow, [authentication](/wallet/recovery/ux-api/#authentication), and how [`moduleAddress`](/wallet/recovery/ux-api/#recovery-modules) selects the Social Recovery Module. To fetch one request by its ID, use [`/v1/recoveries/fetchById`](/wallet/recovery/ux-api/#fetch-recovery-by-id).

## Endpoints at a Glance

| Endpoint | Key params | Returns |
|---|---|---|
| [`GET /v1/recoveries/fetchByAddress`](#fetch-recovery-by-address) | `account`, `chainId`, `moduleAddress?`, `nonce` | Array of recovery requests |
| [`GET /v1/recoveries/listByAddress`](#list-all-recoveries-by-address) | `account`, `chainId`, `moduleAddress?`; optional filters `status`, `executed`, `finalized`, `nonce`, `createdAt`, `orderBy`, `order`, `limit`, `offset` | Array of recovery requests |

## Fetch recovery by address

Fetch all discoverable requests matching a Safe account, chain, module, and recovery nonce. The response is an array, which can be empty. Supply `nonce` as a hexadecimal string; it is the account's nonce on the module named by `moduleAddress`.

### `GET /v1/recoveries/fetchByAddress`

<Tabs>
<TabItem value="example-request" label="Example Request">

```bash
curl -G "https://yourcompany.recovery.candide.dev/v1/recoveries/fetchByAddress" \
  -H 'Authorization: Bearer YOUR_BEARER_TOKEN' \
  --data-urlencode "account=0xD422B9d638a7BA4eBeF9e33Af9456007eAB4ccba" \
  --data-urlencode "chainId=1" \
  --data-urlencode "moduleAddress=0x00480F5ecC008995469fA7e12c70Ef3DC9FEe7fD" \
  --data-urlencode "nonce=0x1"
```

## List all recoveries by address

Lists the recovery requests made for a Safe account on one module, with filtering, pagination, and ordering. The `executed` and `finalized` filters are cross-checked with the on-chain events indexed for that module.

### `GET /v1/recoveries/listByAddress`

<Tabs>
<TabItem value="example-request" label="Example Request">

```bash
curl -G "https://yourcompany.recovery.candide.dev/v1/recoveries/listByAddress" \
  -H 'Authorization: Bearer YOUR_BEARER_TOKEN' \
  --data-urlencode "account=0xD422B9d638a7BA4eBeF9e33Af9456007eAB4ccba" \
  --data-urlencode "chainId=1" \
  --data-urlencode "moduleAddress=0x00480F5ecC008995469fA7e12c70Ef3DC9FEe7fD" \
  --data-urlencode "limit=20" \
  --data-urlencode "offset=0"
```

The response is a plain array with no total count. Request each next page by increasing `offset` by `limit`.

For queries without the `executed` and `finalized` filters, stop when fewer than `limit` items are returned. These two filters are applied after pagination, so queries using either filter can return a short or empty page even when later pages contain matching requests. For those queries, response length does not reliably indicate the end of the results.

Choosing between the two endpoints:

- **`/v1/recoveries/fetchByAddress`**: Use when you know the exact nonce. Ideal for checking a specific pending request or looking up the current recovery state.
- **`/v1/recoveries/listByAddress`**: Use when you need to query multiple requests with filtering, pagination, or sorting. Better for dashboard UIs showing recovery history.
